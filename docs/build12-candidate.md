# Build 12 — Live Activity natural-end QA

Build identity `0.1 (12)`.

This focused candidate retains build 11 enforcement/session behavior and addresses the observed Live Activity cleanup failure with an honest bounded completion bridge. The iOS 26.5 SDK exposes `ActivityUIDismissalPolicy.after(_:)` only as the dismissal policy of an already-ended Activity; it does not schedule a future `end` while preserving the active presentation. Calling `end` with `.after(fixedEnd)` would terminalize the Activity immediately, so no OS-scheduled local dismissal is supported for this requirement.

After durable natural-expiry and Managed Settings reconciliation return, the DeviceActivity monitor launches one detached ActivityKit batch operation for the deduplicated exact `(session ID, immutable end, bedtime/focus kind)` fences. The synchronous callback performs one configured/nominal semaphore wait against one absolute **750 ms** deadline for the entire batch. This is not a guaranteed wall-clock callback bound under preemption, scheduling, or an extension watchdog. Results are the privacy-minimal aggregate `no matching activity`, `ended N`, `bounded wait timed out`, or `presentation cleanup failed`; none can throw into, roll back, delay before, or alter enforcement. Diagnostics are appended after reconciliation to an isolated App Group `UserDefaults` key under a separate bounded cross-process lock, normalized to the final 16 entries, and shown in Developer diagnostics, without changing runtime `operationStatus`/`lastError`. If the extension is killed or ActivityKit does not enumerate the host activity, foreground/relaunch remains the stale presentation fallback.

Build-12 owner device evidence (installed 2026-09-14): start/end enforcement and recurrence passed, but with the host closed the Live Activity did not disappear at natural end; it became stale and showed “Status may be out of date.” This failure means build 12 is not an automatic-dismissal pass. Foreground fallback status was not confirmed. The source-only bounded bridge still requires a new device run and makes no success claim.

Terra medium previously accepted the two-commit source fix with no P0/P1/P2 findings. This follow-up changes the callback completion behavior and diagnostics; it requires fresh review and validation. Do not bump build/install/change schedules in this source-only follow-up.
