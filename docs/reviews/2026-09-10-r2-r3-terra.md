## First reviewer report — snapshot

### P1 — Runtime stops accepting locks after 64 historical sessions
`Shared/RuntimeContracts.swift:~490-510` caps `sessions` at 64, but no lifecycle path prunes terminal `.expired`/`.released` sessions. Every scheduled occurrence is retained forever.

**Path:** after 64 daily starts (earlier with manual locks), monitor start appends session; `context.commit()` fails document validation. The new occurrence is not reliably applied.

**Fix:** prune terminal sessions under the transaction while retaining a bounded terminal-occurrence identity sufficient to suppress late callbacks; add a >64-occurrence regression including duplicate late callback behavior.

### P2 — Allow-only category selections are ignored during effective-policy composition
`ScreenTimeCoordinator.swift:607-619`; `Extensions/DeviceActivityMonitor/MonitorExtension.swift:184-196`.

The UI permits/categories describe allowance, and summaries validate/count `categoryTokens`, but allow-only enforcement intersects only `applicationTokens` and `webDomainTokens`. Category tokens never contribute to the exception set. Thus a selected category does not preserve its apps as intended (and the UI claim that categories are expanded is unsupported by this production path).

**Fix:** implement and test a real category-to-app/domain exception expansion, or reject category selections in allow-only mode and correct the copy. Test one allow-only session and overlapping same-mode sessions containing categories.

### P2 — Persisted recovery/session relationships are not validated
`Shared/RuntimeContracts.swift:~510-550`; `PhoneLockbox/ScreenTimeCoordinator.swift:94-167`.

`RuntimeStoreDocument.validate()` validates the commitment’s internal 900-second encoding but not that every commitment ID exists, is a current effective/recovery-pending session, nor that recovery-pending sessions correspond to the one commitment. Corrupt but decodable state can present an actionable recovery request and release an active session that was never transitioned to recovery pending.

**Fix:** enforce bidirectional document invariants: commitment targets must be nonempty existing effective sessions and recovery-pending IDs must exactly match it; reject orphan/terminal/unknown targets. Add decode regressions for each mismatch.
